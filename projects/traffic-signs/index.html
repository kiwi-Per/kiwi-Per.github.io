Does a bigger network make a better classifier?

We trained five CNNs to recognise 23 classes of traffic signs, from a single convolutional layer up to a 24.6-million-parameter ResNet50. The biggest model came last, and a lightweight network built for phones won. Looking back, the more interesting lessons were in the data pipeline.

Team: Evan Ng, Kyi Wai, Mario Hanzel and Sydney Sim. Code: github.com/syd9191/Traffic-Sign-Classifier

In short
  • MobileNetV2, a small pretrained network, beat ResNet50, which is about eight times larger.
  • The reported results are optimistic. Our data loader reshuffled every epoch, so about two thirds of the test photos had been used for training.
  • ResNet50 probably failed because of its input format, not its size. That is the first experiment I would rerun.

    Augmentation playground

    The raw dataset was small and imbalanced (4,896 images, heavily skewed to a few classes). We undersampled to the median of 198 per class, then topped every class up to 400 with random rotations, zooms and brightness shifts. We avoided flips on purpose, because a mirrored "turn left" sign means "turn right". Try the same transformations on real samples from the dataset.

    Why we got these results

    After the project I went back through the data pipeline asking one question: what would these numbers look like if the test set were truly unseen? The short answer is that they'd likely be lower. Here's why, and what I'd change.

    01The test set changed every epoch

    We split the data by taking the first 70% of batches for training, the next 20% for validation and the rest for testing. But Keras's image_dataset_from_directory reshuffles its file order every time the dataset is iterated, so each epoch drew a different 70%. I simulated the same shuffle: by the end of training, about two thirds of the "test" images had already appeared in training batches.

    Run the simulation yourself

    Same settings as our notebook: 9,200 photos, batches of 256, a shuffle buffer of 8 batches, the first 25 batches for training and the last 752 photos for testing. The share levels off near two thirds, because photos at the very end of the file order can never reach the training batches.

    A clue in our own results: the report lists 95, 26, 12 and 2 errors, but the notebook's evaluation shows 87, 27, 11 and 3. A fixed model scored on a fixed test set gives the same count every time, and with this pipeline the test set is never fixed.

    02Augmented copies leaked across the split

    The raw classes ranged from about 108 to 514 photos, roughly a 5:1 imbalance. We capped each class at 198 photos (discarding about 1,000 real ones) and then generated rotated, zoomed and brightened copies up to 400 per class. Only about 40% of the final 9,200 images are distinct photos; the rest are variants of them. Because augmentation happened before the split, a test image was often a slightly rotated twin of a training image.

    So the test mostly measured recognising photos the model had effectively seen, not new signs on a new street. It also helps explain why MobileNetV2 passed 95% validation accuracy by its third epoch: the validation split leaked in the same way.

    03ResNet50 probably failed because of its inputs, not its size

    Pretrained networks expect inputs in the same format they were trained on. Keras's ResNet50 expects raw 0–255 pixels with the ImageNet mean subtracted; we gave it pixels scaled to 0–1, so after its mean subtraction every image looked like an almost uniform, nearly black frame with 1/255 of its normal contrast. Its layers were frozen, including the normalisation layers, so it couldn't adapt. MobileNetV2 expects values from −1 to 1; our 0–1 input was a much milder mismatch.

    Revised takeaway: "bigger isn't better" may be true here, but our ResNet50 result can't show it. The fair test is to rerun ResNet50 with its own preprocess_input. That's the first experiment I'd run next.

    04Small test sets make near-perfect scores fuzzy

    The test set was 752 images, about 33 per class. Even taking the numbers at face value:

    • 2 errors in 752 gives a 95% confidence interval of 99.0%–99.97% accuracy. Respectable, but not "1.00".
    • A perfect F1 on about 33 stop signs is still consistent with a true miss rate of up to about 10%.
    • The early "perfect accuracy on clean data" came from a single leftover batch of just 32 images.
    • 12 vs 2 errors would be a significant difference (p ≈ 0.013) on a shared test set, but ours wasn't shared.

    05What I'd do differently

    • Split by original photo first, save the split to disk, and only then augment the training images.
    • Use each pretrained model's own preprocessing, and compare frozen vs fine-tuned fairly across architectures.
    • Keep the discarded photos and handle imbalance with class weights instead.
    • Report confidence intervals, and repeat training across seeds before ranking models.
