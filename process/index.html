Project 1, Team of 4, TensorFlow / Keras

Traffic sign classification

Goal: Identify the class of a traffic sign in a photo. There are 23 classes. The team compared five convolutional neural networks (CNNs). The team gave more importance to two classes: stop signs and pedestrian-crossing signs.

Open the traffic sign project

1. DataCollect 4,896 photos 2. DataExamine class sizes 3. PreparationBalance and augment 4. PreparationDivide into sets 5. ModelsTrain five CNNs 6. ModelsFine-tune the best 7. EvaluationMeasure results 8. ReviewExamine the pipeline
  1. 1

    Collect the photos

    The dataset has 4,896 photos in 23 folders. Each folder holds one class of sign. The team resized each photo to 128 × 128 pixels.

    4,896 photos23 classes128 × 128 px
  2. 2

    Examine the class sizes

    The classes do not have the same size. The largest class has approximately 514 photos. The smallest class has approximately 108 photos. A model can prefer the large classes if the data stays like this.

    largest ≈ 514smallest ≈ 108ratio ≈ 5 : 1
  3. 3

    Balance and augment the classes

    First, the team removed photos from large classes until each class had a maximum of 198 photos. 198 is the median class size. Then, the team made new photos from the existing photos until each class had 400 photos.

    Each new photo is a changed copy of a real photo. The changes are a random rotation, a random zoom and a random change of brightness. The team did not flip the photos. A flipped "turn left" sign has a different meaning.

    cap: 198 per classtarget: 400 per classtotal: 9,200rotation ±72°zoom ±20%brightness ±20%
  4. 4

    Divide the data into three sets

    The team divided the photos into a training set (70%), a validation set (20%) and a test set (10%). The team divided the data by batches of 256 photos. Each pixel value was divided by 255, so that each value is between 0 and 1.

    train 70%validation 20%test 10% = 752 photos
  5. 5

    Train five CNNs

    The team trained five models: a CNN with one convolution layer, a CNN with three convolution layers, ResNet50, MobileNetV2, and MobileNetV2 with fine-tuning. ResNet50 and MobileNetV2 used weights from ImageNet. Their layers were frozen. Only the new output layers learned.

    Each model used the Adam optimiser. Training stopped when the validation loss did not improve for 5 epochs. The learning rate decreased by half when the validation loss did not improve for 2 epochs.

    Adam, lr 0.001early stop: 5 epochslr × 0.5 after 2 epochs
  6. 6

    Fine-tune the best model

    MobileNetV2 gave the best result. The team then let the last 5 layers of MobileNetV2 learn. The learning rate was smaller (0.0001), so that the pretrained weights changed slowly.

    5 layers unfrozenlr 0.0001
  7. 7

    Measure the results

    The team measured accuracy, the number of wrong classifications, and the F1 score of the stop and pedestrian-crossing classes. The fine-tuned MobileNetV2 had 2 wrong classifications in the test set. ResNet50 had the worst result, with an accuracy of 0.56.

    fine-tuned MobileNetV2: 2 errorsMobileNetV2: 12 errorsResNet50: accuracy 0.56
  8. 8

    Examine the pipeline after the project

    A later review found three problems. First, the data loader shuffled the photos again at each epoch. Thus, the three sets were different at each epoch (see the diagram below). Approximately two thirds of the test photos were also in the training batches of earlier epochs.

    Second, the team augmented the photos before the split. Thus, a test photo was often a rotated copy of a training photo. Third, ResNet50 needs pixel values from 0 to 255 with the ImageNet mean removed. The team gave it values from 0 to 1. This can explain its bad result.

    ≈ 2/3 of test photos seen in trainingaugment before splitwrong input scale for ResNet50

Why the test set was not fixed

The loader changed the order of the photos at each epoch. The split took the first 70% of batches for training. Thus, the same photo (marked ★) was a training photo in epochs 1 and 2, and a test photo at the final test.

Correct procedure: Divide the original photos into the three sets first. Save the division to disk. Then augment only the training photos.

Project 2, Team project, JAX / Flax

Next-character language models

Goal: Predict the next character of English text from the characters before it. The team built two models from zero: an LSTM and a decoder-only transformer. The team compared the two models on the same test text.

Open the language model project

1. DataLoad text8 2. PreparationEncode and divide 3. ModelsDefine two models 4. ModelsSearch settings 5. ModelsTrain fully 6. EvaluationTest on 5M chars 7. ReviewAnalyse the errors 8. ReviewCompare with Shannon
  1. 1

    Load the text

    The data is text8: text from Wikipedia with only 27 characters. The characters are the 26 lowercase letters and the space. The training file has 90 million characters. The test file has 5 million characters.

    27 characterstrain 90Mtest 5M
  2. 2

    Encode and divide the text

    Each character became a number from 0 to 26. The team kept the last part of the training text as a validation set. The transformer used 12.5% for validation. The LSTM used 10%.

    a → 0 … z → 25, space → 26validation 12.5% / 10%
  3. 3

    Define the two models

    The LSTM reads the characters one at a time. It keeps a memory of fixed size and changes the memory after each character. The transformer looks at all earlier characters in its window at the same time. It learns which earlier characters are important.

    LSTM: 4 layers × 512, window 128Transformer: 6 layers, width 256, 4 heads, window 192
  4. 4

    Search for good settings

    The team used Bayesian optimisation (Optuna) to find good settings, for example the learning rate and the number of layers. Each trial trained a model for a short time. For the transformer, a pruner stopped weak trials early, so that more time was available for good trials.

    transformer: 75 trials, 57 stopped earlyLSTM: 100 trials800 steps per trial
  5. 5

    Train the final models

    The team trained each model with the best settings. The transformer trained for 75,000 steps. Its learning rate increased at the start, then decreased slowly to zero. The LSTM trained for 10 epochs. Both models used the AdamW optimiser and gradient clipping.

    transformer: 75,000 stepsLSTM: 10 epochswarm-up + cosine decay
  6. 6

    Test the models

    The team tested each model on all 5 million test characters. The measurements were accuracy, loss and perplexity. The transformer was more accurate than the LSTM.

    transformer: 67.94%LSTM: 66.38%perplexity 2.79 / 2.92
  7. 7

    Analyse the errors

    A later analysis found where the errors occur. The first letter of a word is correct only 21% of the time. These letters cause 39% of the total loss. Context after approximately 16 characters gives only a small improvement.

    first letter: 21% correctspace at word end: 92% correct39% of loss from first letters
  8. 8

    Compare with Shannon (1951)

    Claude Shannon measured how well people predict the next letter of English. He used the same 27 characters. The LSTM did his test again with 2,000 samples. With few known letters, the LSTM was as accurate as people. With 99 known letters, people were more accurate: 80% against 59%.

    1 letter known: 28% vs 29%99 letters known: 59% vs 80%

How the two models use the earlier text

The LSTM keeps one memory and changes it after each character. The transformer looks directly at each earlier character in its window.

Project 3, NUS, Python, scikit-learn, PyTorch, In progress

Weekly stock direction

Goal: Predict if the adjusted close of a US stock or ETF is higher after five trading sessions. Use only data that is available at the close of the current day. Do not let future data enter the training data.

Open the stock direction project

1. DataAudit 17.45M rows 2. DataRebuild calendar 3. PreparationMake 24 features 4. PreparationFreeze the data 5. ModelsCompare 7 models 6. ModelsTest the leader 7. EvaluationScore 2016–17 8. ReviewDivide the target 9. ReviewRelative target 10. ReviewFind the limit
  1. 1

    Audit the raw data

    The source file has 17.45 million daily rows for 8,507 tickers. The audit examined each row. It found incorrect prices, gaps, days with no change, and dates on weekends. The audit did not change the source file. It recorded each problem with its reason.

    17.45M rows8,507 tickers1962–2017
  2. 2

    Rebuild the trading calendar

    "Five rows" is not always "five trading sessions", because some rows are missing. Thus, the project rebuilt the 2005–2017 exchange calendar from the holiday rules. All 3,202 session dates agreed with the reference dates.

    3,202 sessions0 differences
  3. 3

    Make the features and the target

    The project calculated 24 features from present and past prices only. Examples are returns, volatility, bar shape, relative volume and beta. A row is usable only after 64 continuous valid bars. The target is 1 if the close after five sessions is higher. Equal closes are 0.

    24 features64-bar minimum historyties = 0
  4. 4

    Freeze the dataset

    The project calculated a hash of each data file. Each later notebook checks the hash before it starts. Thus, no step can change the data without a record.

    SHA-256 check in each notebook
  5. 5

    Compare seven models

    The models were a constant baseline, ridge, elastic net, an additive spline model, gradient boosting, extra trees and a deep neural network. Each model used the same 200,000 training rows. The diagram below shows how the dates were divided.

    7 models3 development years: 2013–2015200,000 rows per fit
  6. 6

    Test the leading model more

    The additive spline model was the best on log loss and accuracy. The project tested it with more data, a second random seed, calibration, and new fits each quarter. None of these changes gave a consistent improvement.

    up to 1M rows2 seedsquarterly refits
  7. 7

    Score the 2016–2017 holdout

    The project trained the final models on data before 2016. It saved the models before it opened the 2016–2017 outcomes. It used the same models for both years. Confidence intervals came from blocks of 20 dates, because rows on the same date are not independent.

    2.9M holdout rows465 dates20-date blocks
  8. 8

    Divide the target into two parts

    The project divided each label into a market part and an asset part. The market part explains 13% of the label variance for stocks. No model could predict it. The asset part has a small but stable signal (IC ≈ 0.07). The holdout can find only gains larger than 2.1 points.

    market part: 13% (stocks)IC ≈ 0.07smallest detectable gain: 2.1 pts
  9. 9

    Test a market-relative target

    The project trained the same models with a new target: "Did the asset beat the median asset on that date?" The ranking skill did not change much. But the uncertainty became 3.5 times smaller for stocks. The gain became clear: +1.83 points (interval +1.42 to +2.27).

    stocks: +1.83 ptsinterval 3.5× narrowerIC 0.049 → 0.052
  10. 10

    Find the limit for any price feature

    Half of the stock labels come from a move smaller than 2%. For these rows, the label is almost a coin flip. Sheppard's formula connects accuracy to correlation: accuracy = ½ + arcsin(ρ)/π. The project found ρ = 0.060. An accuracy of 60% needs ρ = 0.31.

    Gradient boosting fitted on the same rows reached an IC of 0.30. On new dates, its IC was 0.018. Thus, the additional patterns were noise. The SPY memory of 2005–2009 was gone in 2013–2015.

    ρ found: 0.06060% needs ρ ≈ 0.31boosting: 0.30 → 0.018development years only

How the dates were divided (development year 2015)

Each model learned only from earlier dates. A label needs five more sessions, so labels that end after a boundary were removed ("purged").
